                  How CuteySnowball works

                  1. Pick a starting point

                  You either give it seed papers (DOIs or PDFs) or a keyword query. In keyword mode, we search OpenAlex + Semantic Scholar + Crossref, keep the most relevant hits as seeds, then snowball each.

                  2. Snowball (bi-directional, Wohlin 2014)

                  For every paper in the queue, we ask every enabled source for: backward = the references the paper cites, and forward = the papers that cite it. New hits are merged into the corpus (richer fields win), scored for relevance, and — if a round overflows — only the top-N most relevant survive.

                  3. Relevance score

                  0.45·TF-IDF + 0.25·keyword-Jaccard + 0.15·recency + 0.15·log(citations). Pure-Python, no external ML dependency.

                  4. Stopping

                  Run ends when the snowball saturates (≤1 new eligible paper in a round), hits max_iterations, or reaches max_total_papers.

                  5. Export

                  JSON (with full graph + dependencies), CSV, RIS, BibTeX. Filter by relevance/year/text first.

                  Anti-block by default

                  CuteySnowball ships with the four free academic APIs (OpenAlex, Semantic Scholar, Crossref, OpenCitations) which never block your IP. Google Scholar enrichment (scholarly + scrape-google-scholar-py) is opt-in via env flags and uses rotating free proxies + 8-14s per-host floors.
